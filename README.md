## О проекте

Этот проект — комплексная очистка, трансформация и разведочный анализ (EDA) данных международного агрегатора ресторанов Zomato (данные по городу Бангалор, Индия).

Основные вопросы, на которые я искала ответы:
- Как онлайн-заказ и бронирование стола влияют на рейтинг?
- В каких районах Бангалора самые высокие оценки?
- Какие типы заведений и кухни наиболее популярны?

Результат:  
Датасет приведён к аналитическому виду, выявлены закономерности, которые могут помочь владельцам ресторанов в принятии решений.

## Этапы работы

### 1. Предобработка данных (Data Cleaning)

#### Удаление ненужных столбцов
Убраны колонки, не несущие аналитической ценности:
- url, address, phone — техническая информация
- reviews_list, menu_item, dish_liked — неструктурированный текст
- listed_in(city) — дублирует location

> Результат: осталось 10 релевантных столбцов

#### Переименование и форматирование
- name → restaurant_name
- rate → rating
- approx_cost(for two people) → cost_for_two
- Убраны лишние пробелы в названиях колонок

#### Удаление дубликатов

### 2. Приведение типов данных

#### Столбец rating

Проблема: значения в формате "4.1/5", "NEW", "-", nan, есть лишние пробелы
Решение: создана функция, которая:

· заменяет "NEW" и "-" на NaN
· удаляет /5 и пробелы
· преобразует в float

#### Столбец cost_for_two

Проблема: значения с запятыми: "1,200", есть nan
Решение: удалены запятые, преобразование в float

### 3. Работа с пропусками

Столбец - Пропуски до - Метод заполнения
rating - 5 097 (14.5%) - KNNImputer (5 соседей)
cost_for_two - 221 - KNNImputer
rest_type - 156 - "no_data" → затем объединение редких
cuisines - 33 - "no_data" → затем объединение редких
location - 14 - объединение редких

Почему KNN для рейтинга?
Рейтинг зависит от других числовых признаков (количество голосов, стоимость). KNN использует эту связь для более точного заполнения, чем среднее или медиана.
